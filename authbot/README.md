# WaysGram AuthBot

Единый сервер WaysGram и Telegram-бот авторизации. Процесс запускает Telegram-бота и HTTP API на одном приложении FastAPI; аккаунты, виртуальные номера, сессии, сообщения, балансы и подарки используют одну SQLite-базу.

## Виртуальные номера и вход

Бот выдаёт уникальный внутренний идентификатор формата `+1` и десять цифр. Это **виртуальный идентификатор WaysGram**, а не номер мобильного оператора: он не принимает звонки или SMS и используется только для входа в WaysGram.

Бот самостоятельно создаёт шестизначный одноразовый код. При входе через приложение пользователь запрашивает код, получает уведомление от AuthWaysGram_bot и открывает кнопку «Получить код». Код хранится в базе в зашифрованном виде, имеет ограниченный срок действия и лимит попыток. После успешной проверки API выдаёт сессию приложения. В базе сохраняется только SHA-256 хеш токена сессии; срок сессии — 30 дней.

Бот не читает SMS и не запрашивает коды личных аккаунтов официального Telegram. Для отдельного self-hosted MTProto-сервера WaysGram поддерживается доставка его собственного кода входа через подписанный webhook; это не код авторизации в официальной сети Telegram.

### Доставка кодов входа self-hosted MTProto-сервера

AuthBot может быть каналом доставки OTP для отдельного self-hosted MTProto-сервера, поддерживающего протокол webhook v1 (например, telesrv/OwpenGram). Сервер сам генерирует и проверяет код; AuthBot только доставляет этот же код пользователю через `@AuthWaysGram_bot`.

Для включения:

1. На Bothost добавь переменную `TELESRV_OTP_WEBHOOK_SECRET` в окружение AuthBot. Это отдельный длинный случайный секрет; сохрани его конфиденциально.
2. На MTProto-сервере задай те же значения:
   ```env
   TELESRV_PHONE_CODE_DELIVERY_PROVIDER=webhook
   TELESRV_PHONE_CODE_LENGTH=6
   TELESRV_OTP_WEBHOOK_URL=https://<домен-authbot>/v1/otp/deliveries
   TELESRV_OTP_WEBHOOK_SECRET=<тот-же-секрет>
   ```
3. Пользователь должен пройти CAPTCHA в AuthWaysGram_bot и получить виртуальный номер `+1XXXXXXXXXX`. Сервер должен отправлять `login_sms` с каналом `sms` и шестизначным кодом.

Маршрут `POST /v1/otp/deliveries` проверяет HMAC-SHA256 подпись, временную метку, назначение и подтверждение виртуального номера. Для номера принимаются оба представления одного виртуального US-идентификатора: `+1XXXXXXXXXX` и нормализованный `1XXXXXXXXXX`, который отправляет telesrv. Перед поиском владельца номер приводится к `+1XXXXXXXXXX`; номера других стран отклоняются. Повтор того же `delivery_id` не отправляет OTP повторно; повторное использование ID с другим телом отклоняется. Код сохраняется в AuthBot в зашифрованном виде и отправляется в личный чат бота.

Этот маршрут принимает только коды собственного self-hosted WaysGram MTProto-сервера. Он не получает, не запрашивает и не пересылает коды входа в официальную сеть Telegram. Он также не заменяет MTProto-сервер: сам AuthBot остаётся HTTP API и Telegram-ботом.

## Запуск

### Docker Compose

В репозитории есть `Dockerfile`, `docker-compose.yml` и безопасный шаблон `.env.example`. Для размещения на сервере:

1. Клонировать репозиторий на Docker-хост.
2. Скопировать шаблон: `cp .env.example .env`.
3. Заполнить в `.env` значения `BOT_TOKEN`, `INTERNAL_API_TOKEN` и `OTP_FERNET_KEY`.
4. Для полного каталога подарков дополнительно задать `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`. Без них AuthBot переключится на ограниченный резервный Bot API-каталог.
5. Запустить: `docker compose up -d --build`.
6. Проверить состояние: `docker compose ps`; endpoint проверки доступен на `http://127.0.0.1:8081/health`.

Compose создаёт постоянный named volume `waysgram_data` для SQLite. Не удаляй его при обновлении контейнера. Для удалённого Android-клиента API должен быть опубликован через HTTPS reverse proxy или HTTPS ingress; не открывай порт API напрямую в публичный интернет без TLS. В GitHub Actions Android-репозитория адрес внешнего HTTPS endpoint задаётся секретом `WAYSGRAM_API_BASE_URL`.

### Запуск в Termux (локальное тестирование)

Этот сценарий предназначен для короткого локального тестирования, когда Android-приложение и AuthBot запущены на одном устройстве. Для подключения с других устройств используй VPS и HTTPS reverse proxy.

1. Установи Termux из доверенного источника и открой его.
2. Клонируй репозиторий:
   `git clone https://github.com/WeteroScript/WaysGram-AuthBot.git`
3. Перейди в каталог и запусти установщик:
   `cd WaysGram-AuthBot && bash scripts/run-termux.sh`
4. При первом запуске скрипт создаст `.env` из шаблона и остановится, чтобы ты заполнил секреты.
5. Открой `.env`, задай `BOT_TOKEN`, `INTERNAL_API_TOKEN`, `OTP_FERNET_KEY` и свой Telegram ID в `ADMIN_ID`.
6. Для полного MTProto-каталога добавь `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`; без них будет доступен резервный Bot API-каталог.
7. Повтори `bash scripts/run-termux.sh`.

Для локального Android-клиента API-адрес должен быть `http://127.0.0.1:8081`. Не используй этот HTTP-адрес для удалённых клиентов через интернет; для них нужен HTTPS.

### Ручной запуск

Требуется Python 3.11+.

1. Установить зависимости: `pip install -r requirements.txt`.
2. Задать `BOT_TOKEN`, `INTERNAL_API_TOKEN` и `OTP_FERNET_KEY` в переменных окружения.
3. Запустить сервис командой из Procfile: `web: python bot.py`.

`BOT_TOKEN` не хранится в исходниках. Создать `OTP_FERNET_KEY` можно командой:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Создать случайный внутренний токен можно командой:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Сгенерированный `OTP_FERNET_KEY` нужно сохранить в секретах хостинга и не менять между перезапусками: он нужен для расшифровки ранее сохранённых кодов. Сервис использует long polling Telegram и одновременно поднимает HTTP API. API слушает `INTERNAL_API_PORT`, затем `PORT`, по умолчанию — 8081. Для продакшена необходим постоянный диск для `DATABASE_PATH`; временное файловое хранилище может потерять базу при перезапуске.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Обязательный токен Telegram-бота |
| `TELEGRAM_API_ID` | Необязательный API ID для bot-authenticated MTProto; нужен для полного каталога |
| `TELEGRAM_API_HASH` | Секретный API hash; используется вместе с `TELEGRAM_API_ID` |
| `ADMIN_ID` | Telegram ID главного администратора; по умолчанию 8888957702 |
| `DATABASE_PATH` | Путь к SQLite; по умолчанию `data/waysgram_authbot.sqlite3` |
| `MESSENGER_DATABASE_PATH` | Путь ко второму файлу SQLite (сообщения, группы, каналы, подарки); по умолчанию `<имя основного файла>_messenger.sqlite3` рядом с ним |
| `INTERNAL_API_TOKEN` | Секрет для внутренних серверных маршрутов |
| `OTP_FERNET_KEY` | Постоянный ключ шифрования одноразовых кодов |
| `INTERNAL_API_HOST` | Адрес привязки API; по умолчанию `0.0.0.0` |
| `INTERNAL_API_PORT` | Порт API; по умолчанию используется `PORT`, затем 8081 |
| `PUBLIC_API_BASE_URL` | Публичный origin API для ссылок-приглашений; задай внешний HTTPS-домен, если приложение работает за reverse proxy |
| `LOG_LEVEL` | Уровень логирования; по умолчанию `INFO` |
| `WAYSGRAM_TON_ADDRESS` | Адрес сервисного TON-кошелька для пополнения звёзд; пусто — раздел TON в клиенте показывает «не настроено» |
| `WAYSGRAM_STARS_PER_TON` | Курс пополнения; по умолчанию 500 звёзд за 1 TON |
| `WAYSGRAM_TON_WATCHER_SECRET` | Секрет вотчера: без него `POST /api/internal/ton/deposits` отвечает 503 |
| `WAYSGRAM_TON_WITHDRAWALS` | `1` включает заявки на вывод TON; по умолчанию вывод выключен |
| `WAYSGRAM_FRAGMENT_COMMISSION_PERCENT` | Комиссия рынка юзернеймов, проценты; по умолчанию 5, допустимо 0–50 |

## Начальные балансы

При первом создании аккаунта WaysGram сервер одной SQL-транзакцией начисляет 5 000 внутренних Stars и 15 внутренних Gram. Повторное обновление профиля или повторная синхронизация номера не выдают бонус повторно. Обе операции записываются в `economy_transactions` как `welcome_bonus`.

## API приложения WaysGram

Клиентские маршруты используют Bearer-сессию. Для получения сессии пользователь должен иметь виртуальный номер и пройти CAPTCHA в AuthWaysGram_bot. Все идентификаторы пользователей в API — это реальные Telegram ID соответствующих аккаунтов WaysGram; отдельная таблица пользователей для второго backend не создаётся.

### Коллекционные юзернеймы (свой Fragment)

Публичного API у fragment.com нет, поэтому рынок юзернеймов работает на звёздном ledger
WaysGram. Владение хранится в `collectibles` и заселяется из `accounts.username` при
миграции: имя, которое уже стоит на аккаунте, нельзя «купить» у самого себя.

- `GET /api/collectibles?section=market|auctions|mine` — витрина: фикс-цена, аукционы, свои имена.
- `GET /api/collectibles/{name}` — карточка: владелец, цена, аукцион, заморозка, история смен.
- `PUT /api/collectibles/{name}/listing` — `{"price_stars":N}`; выставить может только владелец из базы.
- `DELETE /api/collectibles/{name}/listing` — снять с продажи.
- `POST /api/collectibles/{name}/buy` — покупка по фикс-цене (нужен `Idempotency-Key`). Одна транзакция:
  списание покупателю, выплата продавцу минус комиссия (`WAYSGRAM_FRAGMENT_COMMISSION_PERCENT`, по умолчанию 5 %), смена владельца и проводки
  `username_purchase:<listing>` / `username_sale:<listing>`. После покупки имя заморожено на сутки.
- `POST /api/collectibles/{name}/claim` — купить свободное имя у сервиса (цена от длины, `system_price`).
- `POST /api/collectibles/{name}/auction` — `{"min_bid_stars":N,"duration_hours":H}`; `DELETE` отменяет и
  возвращает замороженную ставку.
- `POST /api/collectibles/{name}/bid` — ставка холдит звёзды (`username_auction_hold`), перебитая
  возвращается; ставка в последние 5 минут продлевает торги на 5 минут. Расчёт закрывает аукцион
  лениво при чтении карточки и в фоновом воркере, поэтому рестарт сервера ничего не теряет.
- `GET /api/me/ton` — адрес пополнения, `memo = wg:<telegram_id>`, курс, история.
- `POST /api/me/ton-withdraw` — `{"stars":N,"address":"..."}`; создаёт заявку в `ton_payouts`, включается
  `WAYSGRAM_TON_WITHDRAWALS=1`.
- `POST /api/internal/ton/deposits` — приём от вотчера (`X-WaysGram-Ton-Secret`): `memo`, `tx_hash`,
  `amount_nanoton`. Повторный `tx_hash` отвечает 409 и звёзды второй раз не начисляет.

Вотчер запускается отдельно: `WAYSGRAM_SERVER_URL=... WAYSGRAM_TON_ADDRESS=... WAYSGRAM_TON_WATCHER_SECRET=... python3 scripts/ton_watcher.py`.

### Авторизация и профиль

- `POST /api/auth/request-code` — JSON `{"phone":"+1XXXXXXXXXX"}`; запросить код. Уведомление приходит через AuthWaysGram_bot, код пользователь забирает в боте. Для каждого виртуального номера действует лимит запросов; дополнительные запросы ограничиваются также на уровне IP.
- `POST /api/auth/verify-code` — JSON `{"phone":"+1XXXXXXXXXX","code":"123456"}`; проверить код и получить `token`.
- `POST /api/auth/refresh` — продлить действующую сессию.
- `POST /api/auth/logout` — завершить текущую сессию.
- `GET /api/me` и `PATCH /api/me` — получить или обновить username и отображаемое имя.
- `GET /api/users?q=...` и `GET /api/users/{telegram_id}` — поиск и просмотр публичного профиля.

### Переписка и каналы

- `GET /api/conversations` — список диалогов с последним сообщением.
- `GET /api/messages?with={telegram_id}` — последние сообщения; `after_id` — новые после указанного ID; `before_id` — предыдущая страница истории. Одновременно указывается только один курсор.
  Для активного диалога можно добавить `after_id` и `wait_seconds=20`: API подождёт новые сообщения до 20 секунд и вернёт их сразу после появления. Для обычной загрузки истории `wait_seconds` не требуется.
- `POST /api/messages` — JSON `{"recipient_id":123,"body":"Текст"}`; отправить личное сообщение. Поддерживает `Idempotency-Key` для безопасного повтора после сетевого сбоя.
- Карточка контакта в ЛС, избранном, группах или каналах: `POST /api/messages`, `/api/groups/{id}/messages` или `/api/channels/{id}/messages` с `contact` (`name` либо `first_name`/`last_name`, `phone`, необязательные `email` и `vcard`). Сохраняется пользовательский снимок vCard (не более 16384 символов, без NUL); это не подтверждённая учётная запись WaysGram. Старые карточки name/phone/email сохраняются при миграции. Карточки можно пересылать между чатами через `/api/forward`; прежний маршрут пересылки одного ЛС пока отклоняет их. Карточка в публичном канале доступна его аудитории. Нативный мост подключён, проверка на устройстве не проводилась.
- `DELETE /api/conversations/{peer_id}/messages?for=me|all&max_id=...` — очистить личную историю у себя или у обоих (включая избранное), опционально до указанного положительного ID включительно. По умолчанию `for=me` и без ограничения ID. Для `for=me` партнёр сохраняет историю; `for=all` удаляет сообщения и их привязанные метаданные, но не удаляет файлы владельцев и подарки из инвентаря. Изменения и события для синхронизации сохраняются в одной транзакции. Ожидающие push для затронутых получателей удаляются, но уведомления, уже отправленные или переданные отправщику, отозвать нельзя. Повтор с тем же конечным `max_id` не затронет более новые сообщения; неограниченный запрос может затронуть сообщения, пришедшие до его повторного выполнения. Диапазоны по дате и групповая очистка не поддерживаются. Нативный Android-мост добавлен, проверка на устройстве не проводилась.
- `POST /api/forward` — атомарная пересылка до 20 сообщений из одного чата в другой: `{"source_scope":"dm","source_peer_id":123,"target_scope":"group","target_peer_id":456,"message_ids":[1,2],"silent":false,"drop_author":false,"drop_media_captions":false}`. Типы: `dm`, `group`, `channel`; `source_peer_id` для ЛС — собеседник (для избранного — собственный ID). Проверяются права чтения и отправки, блокировки, лимиты и slow mode. Альбомы получают новый ID; имя автора сохраняется снимком. Повтор с тем же `Idempotency-Key` и телом не создаёт копии, а с изменённым телом возвращает 409. Обычная геолокация и контакт копируются как статические снимки; подарки из ЛС пока не пересылаются. При повторе проверяются актуальные права и доступность исходных сообщений.
- `GET /api/channels`, `GET /api/channels/{id}` — список и карточка канала.
- `POST /api/channels` — создать канал; JSON содержит `title`, `username` для публичного канала и `is_public` (boolean). Для приватного канала передай `is_public: false`; сервер вернёт `invite_link`.
- `GET /api/channels/invites/{token}` — проверить приглашение без вступления.
- `POST /api/channels/join` — вступить по `invite_link` или `invite_token`.

Для корректных внешних ссылок за reverse proxy задай `PUBLIC_API_BASE_URL=https://<публичный-домен>`. Для текущего размещения WaysGram на Bothost Dockerfile и Compose используют `PUBLIC_API_BASE_URL=https://bot-1793554244-6434-weterochina.bothost.tech` по умолчанию; значение из окружения имеет приоритет. При запуске через Procfile или собственную команду запуска добавь эту переменную в окружение сервиса. Без неё сервер использует origin текущего HTTP-запроса.
- `GET /api/channels/{id}/messages` — получить публикации. `before_id` загружает более старую страницу, `after_id` — новые публикации; одновременно использовать оба курсора нельзя. `limit` — от 1 до 100, по умолчанию 100.
  Для ленты в открытом экране поддерживается `wait_seconds=20` вместе с `after_id`; максимальное ожидание — 20 секунд.
- `POST /api/channels/{id}/messages` — опубликовать сообщение; доступ владельцу или администратору канала. Поддерживает `Idempotency-Key`.
- `POST /api/channels/{id}/messages/album` — атомарно опубликовать альбом из 2–10 фотографий и/или видео; подпись у первого элемента, общий ID и порядок у всех элементов. Поддерживает `Idempotency-Key` и `silent`.
- `POST /api/channels/{id}/admins` и `DELETE /api/channels/{id}/admins/{telegram_id}` — управление администраторами канала его владельцем.
- `DELETE /api/channels/{id}` — удалить собственный канал.

Лимит текста сообщения — 4000 символов. Ограничение отправки: 30 личных сообщений в минуту и 20 публикаций канала в минуту. Истории поддерживают инкрементальное чтение через `after_id`.

### Группы

- `GET /api/groups` — группы текущего пользователя.
- `POST /api/groups` — создать группу; JSON содержит `title`, необязательные `username` и `description`.
- `GET /api/groups/{id}` — сведения о группе и участниках; доступ только участникам.
- `POST /api/groups/{id}/members` — добавить участника по `telegram_id` или `username`; требуется роль владельца или администратора.
- `DELETE /api/groups/{id}/members/{telegram_id}` — покинуть группу или удалить участника с проверкой роли.
- `POST /api/groups/{id}/admins` / `DELETE /api/groups/{id}/admins/{telegram_id}` — назначение и снятие администраторов владельцем.
- `GET /api/groups/{id}/messages` и `POST /api/groups/{id}/messages` — история и отправка текста. История поддерживает `before_id` для старых и `after_id` для новых сообщений (не одновременно), а также `limit` от 1 до 100, по умолчанию 100. Одиночная отправка поддерживает `Idempotency-Key`: повтор идентичного запроса в течение 7 дней возвращает прежний результат без второго сообщения; смена тела с тем же ключом даёт 409, а доступ повторно проверяется.
- `POST /api/groups/{id}/messages/album` — атомарно отправить участникам альбом из 2–10 фотографий и/или видео; проверяет членство, slow mode и reply target, поддерживает `Idempotency-Key` и `silent`.
  Для открытого экрана группы чтение с `after_id` поддерживает `wait_seconds=20`.

Создатель получает роль владельца. Проверка членства выполняется для каждой операции чтения и отправки.

### Изображения, документы и медиа в сообщениях

- `POST /api/media/images` — загрузить статичное изображение JPEG, PNG или WebP.
- `POST /api/media/documents` — загрузить JPEG/PNG/WebP как файл, PDF, TXT, CSV, архивы ZIP/RAR/7Z/TAR/GZIP/BZIP2/XZ, видео MP4/M4V/MOV/WebM/MKV или аудио MP3/M4A/OGG/OPUS/FLAC/WAV. Передай исходные байты в теле запроса, соответствующий `Content-Type` и имя файла в percent-encoded заголовке `X-Filename`.
- `GET /api/media/{media_id}` — получить вложение после проверки сессии и доступа к соответствующему сообщению/чату.
- `GET /api/media/shared?scope=dm|group|channel&peer_id=...` — получить общие вложения чата с необязательными фильтрами `kind=image|video|audio|document`, `before_id` и `limit`.
- `POST /api/messages`, `POST /api/groups/{id}/messages`, `POST /api/channels/{id}/messages` — прикрепить загруженный файл через поле `media_id`. При пустом тексте сервер подставляет подпись по типу и имени вложения. Поле `silent: true` для одиночного сообщения не отправляет push (в том числе тихий); сообщение и событие остаются в истории. По умолчанию `silent: false`; допускается только boolean. Android-мост передаёт флаг для текста и файла; полноценные тихие уведомления и проверка на устройстве пока не завершены.
- Статическую геопозицию можно отправить через `location: {"latitude": 52.0, "longitude": 4.3, "label": "Место"}` в `POST /api/messages`, `/api/groups/{id}/messages` и `/api/channels/{id}/messages`; `label` необязателен. Координаты и доступ проверяются, совмещать позицию и файл нельзя. Место с названием может дополнительно содержать `venue: {"address": "...", "provider": "...", "venue_id": "...", "venue_type": "..."}`: значения строковые и ограничены по длине. Результат отправки содержит объект `location.venue`, а история и пересылка — JSON-строку `location_venue_json`; старые точки имеют пустую строку. Позиция и данные места сохраняются в истории и при пересылке как снимок; live-трансляция — отдельная функция. Нативный мост подключён для одиночной отправки, но на устройстве не проверен.
- `POST /api/messages/album` — атомарно отправить в личный чат альбом из 2–10 принадлежащих отправителю фотографий и/или видео через массив `media_ids`.
- `POST /api/groups/{id}/messages/album` и `POST /api/channels/{id}/messages/album` — тот же формат альбома для групп и каналов. Все элементы получают общий `media_album_id`, `media_album_index` и `media_album_count`; подпись и reply context сохраняются у элементов альбома. Создание выполняется одной транзакцией, поддерживается `Idempotency-Key`, push-уведомление отправляется один раз на альбом.

Обычные фотографии через `/api/media/images` ограничены 10 MiB, максимальная сторона — 8192 пикселя, общий лимит — 40 мегапикселей; сервер пересохраняет их, удаляя метаданные. JPEG, PNG и WebP через `/api/media/documents` проверяются как статические изображения в тех же пределах разрешения, но сохраняются как файлы с исходными байтами и именем; старые вложения без признака документа автоматически не переклассифицируются. Остальные документы и такие файлы ограничены 25 MiB. PDF проверяется по сигнатуре и завершающему маркеру; TXT/CSV принимаются только как UTF-8 без NUL и недопустимых управляющих символов и сохраняются побайтно, включая BOM и исходные переносы строк. Видео, аудио и ZIP проверяются по допустимому расширению, MIME-типу и файловой сигнатуре; архивы не распаковываются сервером. HTML, SVG, исполняемые файлы и неподдерживаемые типы отклоняются. Изображения, видео и аудио отдаются inline; документы и ZIP — как attachment. Медиаальбомы в личных чатах, группах и каналах принимают только фото/видео, от 2 до 10 файлов; создание всех сообщений и фиксация метаданных альбома выполняются одной транзакцией. Для уже существующих баз поля альбома добавляются миграцией при запуске. Для всех ответов применяется `X-Content-Type-Options: nosniff`.

На аккаунт действует общая квота 100 MiB и ограничение 30 загрузок в час для медиа. Вложения доступны владельцу и участникам соответствующего диалога/группы; посты публичных каналов доступны по правилам канала. Android-клиент WaysGram отправляет и отображает сгруппированные фото/видео альбомы в личных чатах, группах и каналах. При выборе 2–10 фотографий и/или видео клиент загружает их последовательно и отправляет одним альбомом; элементы отображаются в общем вертикальном блоке, подпись сохраняется у первого элемента. Документы, аудио и смешанные подборки отправляются отдельными сообщениями. ZIP и документы можно сохранить через системный диалог Android; видео доступно для воспроизведения и сохранения. Анимированные изображения и встроенная запись голосовых сообщений ещё не реализованы.

Файлы сохраняются в `waysgram_media` рядом с SQLite-файлом. В Docker Compose обе папки находятся в постоянном томе `/data`. Резервные копии должны включать и SQLite, и каталог медиа.

### Внутренний BotFather

- `GET /api/bots` — список собственных ботов.
- `POST /api/bots` — создать бота; JSON: `name`, `username` (оканчивается на `_bot`), необязательные `about` и `description`. Токен возвращается только при создании.
- `GET /api/bots/by-username/{username}` — получить публичную карточку бота.
- `GET /api/bots/{id}`, `PATCH /api/bots/{id}`, `DELETE /api/bots/{id}` — управление собственным ботом.
- `POST /api/bots/{id}/token/reset` — перевыпустить токен; старый токен отзывается.
- `GET /api/bots/{id}/commands` и `PUT /api/bots/{id}/commands` — настройка списка команд.
- `POST /api/bots/{id}/messages` и `GET /api/bots/{id}/messages` — чат пользователя с внутренним ботом.
  История с `after_id` поддерживает `wait_seconds=20` для ожидания ответов без частых пустых запросов.
- `GET /api/bot-api/getUpdates?offset=...` — получить входящие сообщения по токену бота.
- `POST /api/bot-api/sendMessage` — отправить ответ пользователю по токену бота.

Каждый пользователь может иметь до 20 активных ботов. Токены хранятся в базе только в виде SHA-256 хеша. Это внутренняя система WaysGram: созданные здесь боты не становятся ботами Telegram и не получают доступ к Telegram Bot API.

### Каталог подарков Telegram из MTProto

- `GET /api/telegram/gifts` — полный каталог `payments.getStarGifts`, если настроен MTProto; в противном случае — резервный список Bot API.
- `GET /api/telegram/gifts/{gift_id}/sticker` — получить файл стикера через авторизованный серверный proxy.
- `POST /internal/v1/telegram/gifts/sync` — принудительно обновить снимок каталога; требуется `X-Internal-Token`.

**Основной источник — MTProto `payments.getStarGifts`.** AuthBot авторизует бота с `BOT_TOKEN`, `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`. Сессионный файл бота хранится в `data/`, исключён из Git и получает права владельца процесса. Коды входа пользователей WaysGram для каталога не используются.

**Модели и узоры улучшений требуют отдельной сессии Telegram-пользователя.** Реальные запросы `payments.getStarGiftUpgradeAttributes` и `payments.getStarGiftUpgradePreview` от бота отклоняются Telegram с `BotMethodInvalidError`. При желании оператор может предоставить предварительно авторизованную пользовательскую Telethon StringSession в секретной переменной `WAYSGRAM_GIFT_USER_SESSION`. Эта сессия используется только для получения атрибутов и загрузки их файлов; обычный каталог остаётся на bot-сессии. Без неё другие функции работают, но новый набор моделей через бота недоступен.

**Безопасность:** StringSession предоставляет полный доступ к Telegram-аккаунту, не только к подаркам. Используйте отдельный доверенный аккаунт оператора, а не аккаунт пользователя WaysGram; не отправляйте сессию, API hash, коды или пароли в чат, Git или журналы. При компрометации завершите соответствующий сеанс в настройках Telegram и создайте новый. Настраивайте только на доверенном хостинге с приватными переменными окружения.

Подготовка выполняется оператором в собственном доверенном терминале с установленными зависимостями `authbot/requirements.txt` и теми же `TELEGRAM_API_ID` / `TELEGRAM_API_HASH`, что у сервера:

```bash
python authbot/scripts/create_gift_user_session.py --output /private/path/gift-user.session
```

Скрипт использует стандартную локальную авторизацию Telethon и создаёт новый файл с правами `0600`, не печатая сессию. Значение из файла нужно **самостоятельно** внести в секретную переменную `WAYSGRAM_GIFT_USER_SESSION` хостинга, затем перезапустить развёрнутый AuthBot. Никогда не передавайте его ассистенту. После этого ожидается сообщение `Gift attribute user session connected`; проверьте синхронизацию и загрузку модели конкретного подарка. При неудаче пользовательской сессии бот продолжит работать, но модели без сохранённого набора будут недоступны.

При успешной загрузке сохраняются поля полного MTProto `StarGift`: идентификатор, документ стикера, стоимость в Telegram Stars, ограниченность, распроданность, premium-требование, лимит на пользователя, остатки, resale-поля, upgrade-цена, даты, фон и признак `auction`. Список обновляется автоматически при запросе, если последняя синхронизация старше 60 секунд. Файлы стикеров скачиваются AuthBot через MTProto и отдаются клиенту через Bearer-защищённый proxy; MTProto document и bot token на Android не передаются.

**Резервный режим:** если `TELEGRAM_API_ID` или `TELEGRAM_API_HASH` не заданы или MTProto временно недоступен, сервис загружает Bot API `getAvailableGifts`. Это только подарки, доступные для отправки AuthBot, а не полный каталог.

В поле `currency` у исходного каталога указывается `telegram_stars`. Это метаданные Telegram и они не означают, что WaysGram списывает Telegram Stars. В WaysGram-магазине используются отдельные значения `price_stars`, `supply` и `sold`, которые задаёт администратор.

Каталог Telegram хранится отдельно от внутреннего `gift_catalog`. Покупка через `POST /api/telegram/gifts/{gift_id}/purchase` — это внутренняя операция WaysGram: она списывает внутренние WaysGram Stars, уменьшает остаток магазина и записывает в инвентарь Telegram Gift ID исходного подарка. Она не отправляет подарок в Telegram, не передаёт Telegram collectible и не выполняет on-chain NFT-транзакцию. Повтор с тем же `Idempotency-Key` не списывает баланс повторно.

Управление ценой и остатком Telegram-подарков доступно только в админ-панели AuthBot. Для этого используется действие «Добавить по Telegram Gift ID»; REST-маршрута изменения цены или остатка для Android-приложения нет.

В разделе «Управление БД → Подарки → Добавить все подарки» бот запрашивает число от 1 до размера активного каталога Telegram. Он добавляет или обновляет первые N записей в исходном порядке, остальные ранее добавленные подарки не изменяются. Чтобы добавить все, введите показанное максимальное число. Цена и положительный остаток копируются из источника; подаркам с нулевым остатком Telegram назначается независимый неограниченный остаток **WaysGram**, чтобы они были видны во внутреннем магазине. Это не означает, что их можно купить или отправить в Telegram. Если в источнике и текущей настройке WaysGram у подарка нет цены, бот до изменения базы попросит общую положительную цену для таких подарков. В резервном режиме используется неполный каталог Bot API.

### Баланс и подарки

- `GET /api/me/wallet`, `GET /api/me/wallet/transactions` — балансы и история операций.
- `GET /api/gifts` — каталог доступных подарков.
- `GET /api/me/gifts`, `GET /api/me/gifts/transactions` — инвентарь и история передач.
- `POST /api/gifts/{id}/purchase` — покупка за Gram. Для защиты от повторного списания поддерживается заголовок `Idempotency-Key` длиной 16–128 символов.
- `POST /api/gifts/transfer` — передача принадлежащего пользователю подарка по серийному номеру и Telegram ID или username получателя. Поддерживает `Idempotency-Key`.
- `POST /api/messages/gift` — атомарно передаёт собственный подарок пользователю и создаёт сообщение в ЛС со снимком атрибутов. Проверяются блокировки и запрет передачи выставленного подарка; `Idempotency-Key` предотвращает повторную передачу и создание сообщения. Передача бесплатна внутри WaysGram и не является операцией Telegram или on-chain NFT. Нативная карточка коллекционного подарка в своём профиле подключена к этому маршруту; Android runtime не проверен.
- `POST /api/gifts/{serial}/upgrade` — улучшение подарка: фиксированные **25 внутренних Stars** один раз за подарок независимо от цены в каталоге Telegram. Уже улучшенный подарок не улучшается повторно (`409`, без списания); успешный повтор с тем же `Idempotency-Key` возвращает прежний результат. При недостатке баланса возвращает `402`, при занятом аукционе или выставлении на продажу — `409`.
  Модель, узор и фон роллятся один раз из **официальных пулов Telegram** (`gift_upgrade_pools.json`, снято из `payments.getStarGifts`) с теми же названиями и теми же шансами (`rarity_permille`, 1000 ‰ = всегда), а фон приходит с оригинальными четырьмя цветами. Ответ содержит `traits`, `unique_num` и `roll_pool` — список кандидатов для анимации прокрутки в клиенте.
  Каждый улучшенный подарок получает **номер внутри своей коллекции** (`Plush Pepe #1`, первая Sakura Flower тоже `#1`), номер хранится в `gift_unique_numbers` и не меняется при передаче; ранее полученные уровни выше 1 сохраняются без изменений.
- `POST /api/gifts/{serial}/sell` — возврат подарка самой WaysGram: **50 %** уплаченной цены, только в первые **7 дней** после получения. Возврат идёт в той же валюте, в которой платили (`stars` или `grams`); подарок убирается из инвентаря, карточка-квитанция в чате остаётся с пометкой `star_gift_sale`. Повтор с тем же `Idempotency-Key` не возвращает баланс дважды; `404` — если подарка нет, `409` — если подарок старше недели, выставлен на продажу или его цена неизвестна.

Покупка атомарно уменьшает баланс и остаток каталога, создаёт экземпляр с уникальным серийным номером `WG-...` и записывает операцию. Повтор того же запроса с тем же ключом идемпотентности возвращает прежний результат. Stars и Gram — внутренние единицы учёта; внешняя оплата и вывод средств этим API не реализованы.

`GET /api/me/gifts` отдаёт по каждому подарку `purchase_asset`, `purchase_price`, `sell_refund`, `sell_refund_asset`, `sellable` и `sellable_until`, а также `upgrade_star_count` (всегда 25) и `unique_num` (номер в коллекции) — клиент показывает «Улучшить за 25» только для обычного подарка и «Продать за N ⭐» при соблюдении условий, а карточка подарка выводится как «Plush Pepe #1» без дополнительных запросов.

### Системные аукционы

- `GET /api/auctions` — список активных и завершённых аукционов; при запросе выполняется завершение аукционов, срок которых истёк.
- `POST /api/auctions/{id}/bid` — ставка в JSON `{"amount":100}`; сумма указывается во внутренних Stars.

В аукцион выставляет подарок администратор через `/admin` → «Аукционы подарков». При создании один экземпляр резервируется из остатка каталога. Новая ставка должна быть не меньше стартовой и строго выше текущей. Сумма лидирующей ставки временно удерживается из баланса; при перебивании предыдущая ставка возвращается прежнему лидеру. После окончания аукциона победитель получает зарезервированный подарок. Если ставок нет, экземпляр возвращается в остаток. Отмена администратором возвращает лидирующую ставку и экземпляр подарка в каталог.

### Внутренние маршруты AuthBot

Маршруты ниже предназначены для доверенных внутренних интеграций и требуют заголовок `X-Internal-Token`:

- `POST /internal/v1/number/resolve` — проверить назначение виртуального номера.
- `POST /internal/v1/auth-code/request` — создать и доставить одноразовый код через Telegram-бота.
- `POST /internal/v1/auth-code/verify` — проверить и погасить код.
- `POST /internal/v1/telegram/gifts/sync` — обновить MTProto-каталог; при отключённом MTProto используется резервный Bot API.

`GET /health` — проверка работоспособности. Клиентские маршруты `/api/...` используют пользовательские Bearer-сессии, а не внутренний секрет.

## Админ-панель

Админ-панель доступна только в личном чате с AuthBot: главный администратор из `ADMIN_ID` (по умолчанию `8888957702`) отправляет боту команду `/admin`. Web-панели и Android-админки нет.

В панели доступны:

- **Статистика:** пользователи, блокировки, номера, активные коды, каналы, группы, внутренние боты, аукционы, личные сообщения, каталог и инвентари подарков, суммарные Stars и Gram.
- **Аккаунты:** поиск по Telegram ID, виртуальному номеру, точному username WaysGram (с `@` или без) и отображаемому имени; карточка, блокировка и разблокировка. В карточке «Выдать подарок» открывает постраничный каталог подарков WaysGram и позволяет ввести количество от 1 до 100. Подарки бесплатно создаются во внутреннем инвентаре выбранного аккаунта, остатки магазина не меняются; это не отправка или покупка в Telegram. Действие записывается в журнал, а получатель видит уведомление в системном чате.
  Рядом доступно **«Выдать NFT-подарок»**: выберите коллекцию, модель, фон и узор. Подписи показывают шансы атрибутов, а подтверждение — также оценку совместного шанса фона и узора при независимом выпадении. Администратор выбирает атрибуты вручную, без розыгрыша. После выбора введите количество от 1 до 150: все подарки получат выбранные атрибуты и отдельные номера в коллекции. Остатки и баланс не меняются.
- **Баланс:** начисление Stars и Gram с записью в журнал операций.
- **Подарки:** полный список каталога с постраничной навигацией, редактирование цены и остатка, скрытие, выдача и передача.
- **Аукционы:** создание и отмена системных аукционов; при отмене возвращаются удержанная ставка и зарезервированный экземпляр подарка.
- **Группы:** просмотр и удаление групп.
- **Внутренние боты:** просмотр и включение/отключение пользовательских ботов.
- **Каналы:** просмотр каналов, владельцев и числа публикаций; удаление канала.
- **Журнал:** операции с балансами, подарками, группами, ботами и административные действия.

**Дополнительные администраторы.** В панели главный администратор выбирает «Добавить админа», вводит Telegram ID или Telegram `@username` и подтверждает показанный ID. Поиск username работает только для тех, кто уже открыл AuthBot; username может измениться, поэтому перед подтверждением проверяйте ID. По ID можно назначить и того, кто ещё не открывал бота. Назначенный пользователь входит в боте командой `/admin` и получает полный доступ к действиям панели AuthBot, кроме назначения и удаления администраторов; статус администратора в приложении WaysGram при этом не выдаётся. Только главный администратор может отозвать доступ через кнопку «Админы». Права хранятся в основной SQLite-базе и сохраняются после перезапуска; назначения, удаления и действия записываются с ID фактического администратора. Смена `ADMIN_ID` меняет главного администратора, но не удаляет ранее выданные права. Блокировка аккаунта проверяется при авторизации, разрешении номера и операциях приложения.

## Текущие ограничения

Серверный API предоставляет авторизацию, профили, личные сообщения, текстовые каналы, группы, внутренний BotFather, балансы, подарки, системные аукционы, загрузку изображений, документов, ZIP, аудио и видео. Фото/видео медиаальбомы поддерживаются в личных чатах, группах и каналах; анимированные вложения и звонки пока не реализованы. Для пользовательских ботов доступны команды, входящие обновления и отправка текстовых ответов; среда исполнения произвольного кода пользователя не размещается на сервере. Каталог подарков по-прежнему требует отдельной загрузки исходных карточек (ID, название, изображения, цена, лимит и признак поддержки аукциона); эти данные не создаются из общих Lottie-анимаций автоматически.


## Две базы данных

Данные разделены на два файла SQLite, которые лежат в одной постоянной папке (`/data`):

| Файл | Что хранит |
| --- | --- |
| `waysgram_authbot.sqlite3` (`DATABASE_PATH`) | аккаунты, виртуальные номера, коды входа, OTP, сессии API, журнал входов, журнал админа |
| `waysgram_authbot_messenger.sqlite3` (`MESSENGER_DATABASE_PATH`) | личные сообщения, группы, каналы, боты, подарки и аукционы, баланс грамм и звёзд (журнал операций), индекс медиа, каталог подарков Telegram |

Как это работает: ко всем соединениям с основной базой второй файл подключается как схема `messenger`. SQLite находит таблицы без указания схемы, поэтому запросы и связи с `accounts` работают как раньше. Код разделения находится в `db_split.py`.

**Обновление с одним файлом.** При первом запуске новой версии таблицы мессенджера автоматически переносятся во второй файл. Перед этим рядом с основной базой сохраняется копия `waysgram_authbot.sqlite3.pre-split.bak`. Перенос проверяется по числу строк, и исходная таблица удаляется только после успешной проверки. Повторный запуск безопасен.

Резервные копии должны включать оба файла и каталог `waysgram_media`. Оба файла должны лежать на постоянном диске.

### Voice transcription

Manual message translation is optional and uses `OPENAI_API_KEY` and `WAYSGRAM_TRANSLATION_MODEL` (default `gpt-6.1-terra`), with confirmation for each translation window in the native client. The server does not persist translation texts; OpenAI receives the selected text. See `docs/messaging-implementation-plan.md` for limits and privacy details.

Voice transcription is optional. Configure `OPENAI_API_KEY` in the AuthBot host environment to enable it. The WaysGram client asks for explicit confirmation before sending an audio attachment to OpenAI. The resulting transcript is cached in the messenger database for that media item; removing an unused media item also removes its cached transcript.
