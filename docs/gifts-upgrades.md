# Улучшение подарков: контракт

Краткая памятка, как WaysGram один раз улучшает обычный подарок до коллекционного.

## Что покупает пользователь

- Цена фиксированная: **25 ⭐** за одно улучшение, списание с внутреннего баланса WaysGram
  (`UPGRADE_PRICE_STARS`), Telegram Stars как платёжный провайдер не участвуют.
- Улучшать можно **любой** подарок: и из каталога Telegram, и «свой» подарок WaysGram без
  `telegram_gift_id`.

## Что меняется на карточке

Telegram бросает три атрибута: **модель**, **узор** и **фон** (фон задаёт четыре цвета —
центр, край, узор, текст). WaysGram использует официальные пулы Telegram
(`authbot/gift_upgrade_pools.json`), поэтому имена, вероятности и цвета совпадают с оригиналом.

**Подарок улучшается только один раз.** Сервер под транзакционной блокировкой
отклоняет повторное улучшение NFT с `409` до списания средств. Повтор запроса с тем же
ключом идемпотентности возвращает прежний успешный результат, не списывая Stars.
Существующие подарки уровня 2 и выше сохраняют текущие характеристики и не меняются.
Модель, узор и фон выбираются один раз и остаются прежними при передаче.

Ограничение: у подарка, которого нет в каталоге Telegram, нет и документов модели/узора,
поэтому у него меняется только фон (модель и узор физически отсутствуют).

## Как модель и узор попадают на карточку

1. Сервер при улучшении синхронизирует набор атрибутов подарка из каталога Telegram
   (`telegram_mtproto_gift_attributes`) и сохраняет `document_id` внутри трейтов
   (`model.document_id`, `pattern.document_id`).
2. Клиент по этому id скачивает официальную анимацию
   (`/api/telegram/gifts/{gift_id}/attributes/{document_id}`) и подставляет её в родную
   карточку `StarGiftSheet`/`GiftCell` — без собственной отрисовки.
3. Пока документ не скачан, карточка показывает уже новый фон; после скачивания инвентарь
   перестраивается и появляется модель.
4. Неудачные скачивания не «залипают»: `WaysGramGiftAttributes.retryFailed()` вызывается при
   каждом обновлении инвентаря.
5. Трейты, улучшенные старым бэкендом (без `document_id`), починяются при чтении
   `/api/me/gifts`: id восстанавливается по позиции/шансу и сохраняется в БД.

## Ролл внутри живого набора Telegram (с 2026-11-18)

Главный источник бага «нет моделей» был в том, что ролл шёл по статическому
`gift_upgrade_pools.json`, а документ потом искался по имени. При локализации/переименовании
имени (или когда Telegram отдавал только `sample_attributes` — по одному атрибуту каждого
вида) документ не находился, и модель не рисовалась.

Теперь:

1. Перед транзакцией апгрейда сервер читает набор атрибутов подарка из Telegram
   (`payments.getStarGiftUpgradeAttributes`, при недоступности — `getStarGiftUpgradePreview`)
   и **бросает модель, узор и фон внутри этого набора**, если в нём есть выбор (≥2 варианта).
   Победитель приходит вместе со своим `document_id` — как у официального клиента, которому
   сервер отдаёт `starGiftUnique` с документами атрибутов.
2. В трейтах рядом с `document_id` хранятся `position` (слот в наборе Telegram) и `pool_size`.
   Если у старого подарка нет `document_id`, клиент сначала ищет имя с нормализацией
   типографики; позицию и уникальный шанс использует лишь для полного набора.
3. Если Telegram отдал единственный образец (`sample`), он не является полным набором.
   По нему нельзя надёжно восстановить другой выпавший документ. Когда полных данных нет,
   статический пул содержит имена и вероятности, но не сами файлы моделей: их отображение
   нельзя гарантировать до восстановления доступа к Telegram.
4. `/api/telegram/gifts/{id}/attributes` теперь отдаёт блок `sync`: `source` = `full` /
   `sample` / `empty`, число строк по видам и сколько из них с документом. По нему видно,
   деградировал ли каталог, без чтения логов.
5. Если у подарка в БД вообще нет строк атрибутов, `/api/me/gifts` ставит синхронизацию в фон
   (`schedule_attribute_sync`) — следующий вход в инвентарь уже починит трейты.

Также исправлено распределение фонов: их шанс читался как «класс редкости» и все фоны были
равновероятны; теперь используется опубликованный permille, как в Telegram.

## Ограничение Telegram: сессия для атрибутов

В реальном BotHost оба метода атрибутов для Astral Shard отклонены с
`BotMethodInvalidError`: Telegram не разрешил их бот-сессии. Статический JSON хранит
имена, но не содержит файлы моделей. Начиная с этой версии оператор может настроить
**отдельную предварительно авторизованную пользовательскую MTProto-сессию** только для
запросов атрибутов и скачивания их документов (`WAYSGRAM_GIFT_USER_SESSION`). Обычный
каталог и работа AuthBot остаются на бот-сессии. Подготовка, риски и защита секрета описаны
в `authbot/README.md`. Без этой настройки не утверждайте, что модели восстановлены.

После получения полного набора сервер пытается сопоставить документы уже существующих
подарков и отдать их приложению без повторной оплаты. Успех сопоставления зависит от
сохранённых трейтов; отдельно проверьте конкретные подарки на развёрнутом сервере и устройстве.
API и HTTP-логи не должны содержать пользовательскую сессию.

## Устойчивость и диагностика

- Полный сохранённый набор не заменяется временной ошибкой или неполным preview. Preview
  повторно проверяется через пять минут, полный набор — через шесть часов.
- Документы сохраняются в базе и могут восстанавливаться после перезапуска сервера; если
  Telegram отклонил устаревшую ссылку на файл, сервер повторно запрашивает атрибуты.
- Для распроданного подарка, включая Plush Pepe, используется анимация модели, если обычный
  стикер каталога недоступен. На клиенте временно неудачные загрузки повторяются.
- Источник `sync.source` и счётчики `sync.kinds` в ответе
  `/api/telegram/gifts/{id}/attributes` показывают, получил ли сервер полный набор (`full`) или
  только образец (`sample`). Если набор отсутствует, проверьте работу MTProto-провайдера,
  настройки `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` и журналы AuthBot. Исходные файлы моделей
  не входят в статический JSON-пул и не могут быть восстановлены только по имени.
- Для применения нужны развёртывание обновлённого AuthBot и новая Android-сборка; серверные
  тесты не заменяют проверку отображения на устройстве.
