# Подарки в профиле: реализация и проверка

1. `GET /api/users/{id}/gifts` отдаёт инвентарь конкретного пользователя с пагинацией. Клиент загружает все страницы; действия владельца остаются ограничены владельцем и сервером. В профиле без общего медиа тоже создаётся секция с вкладкой.
2. Отправитель обычного подарка берётся из последнего события приобретения. Новые сообщения и события связаны через `gift_transactions.message_id`, поэтому повторная передача в ту же секунду не приклеивает старую подпись. У NFT отправитель и подпись не выдаются в инвентаре; история переписки не стирается. При анонимной покупке имя в инвентаре скрыто.
3. Сообщение из формы покупки записывается в связанное сообщение чата и показывается в карточке обычного подарка. Передача текста с форматированием пока не реализована: сохраняется только текст.
4. Для недоступного каталогового файла сервер пробует получить модель через MTProto; Android пробует анимированный и статический варианты. Настоящий исходный стикер или модель должны быть доступны из Telegram на развёрнутом сервере — одна только заглушка не доказывает доступность Plush Pepe.
5. Каждый подарок улучшается только один раз; его модель, узор и фон после этого не перебрасываются. В сохранённый результат записана фактическая доля веса, округлённая до целых промилле (точность отображения 0,1%). Для неполных каталогов веса нормализуются по имеющимся вариантам; для атрибутов только с классом редкости используется оценочное распределение остатка. Это шансы WaysGram, а не гарантия официальных шансов Telegram. Единственный sample больше не подменяет случайно выбранную модель: при неполном наборе документов анимация конкретного результата может быть недоступна.
6. Вложенный список вкладки подключён к обработке видимой высоты и скролла, а обновление сохраняет позицию. Это требует последующей проверки на устройстве.

Проверки без Android-сборки: `python scripts/test_android_gifts.py`, `python scripts/test_android_labels.py`, проверка ZIP и серверный `pytest`. Статические проверки и моки не заменяют сборку и ручную проверку UI, реальной MTProto-сессии и файлов подарка в production.
