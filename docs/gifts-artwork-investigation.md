# Диагностика отсутствующих изображений (Plush Pepe / Heart Locket)

Скриншот с 🎁 в серой плитке похож на нарисованный `placeholderSticker` в
`WaysGramGifts`, а не на изображение Pepe. Это не доказывает конкретную причину
на устройстве: сервер мог не получить файл, мобильный сеанс мог быть отклонён,
приложение могло открыть карточку до завершения загрузки, либо в кеше остался
старый валидный PNG. Серверная локальная копия и обновление открытой карточки
уже были добавлены ранее, но без развёртывания и нового APK в установке их нет.
Повторный запуск старого бота не загружает незакоммиченные файлы. У BotHost
bridge по умолчанию `WAYSGRAM_REF=main`; `WAYSGRAM_COMMIT` может закреплять
старый коммит, а при недоступности GitHub возможен запуск последнего кеша.
`python bot.py --check` у bridge показывает разрешённый коммит и путь без запуска
бота; не публикуйте токены/сессии.

В новой версии исходников Android документ обычного Pepe получил новую локальную
идентичность (сам `gift.id` не меняется). Это позволяет обойти старую заглушку
и отдельный кеш Telegram FileLoader без очистки данных аккаунта. Заодно клиент
не выбирает модель по совпадению вероятности из неполного preview: сначала
совпадает имя, остальные эвристики допустимы только на полном наборе. Эти
изменения потребуют новой APK; только перезапуск сервера клиент не изменит.

У Heart Locket фон может загрузиться даже если документ модели не получен:
пулы имён и фонов сами по себе не содержат анимации. Другая модель этой же
коллекции может быть доступна в кеше или preview, а именно выпавшая — нет.
Данные `sync.source` и `sync.kinds` в авторизованном ответе
`GET /api/telegram/gifts/5868455043362980631/attributes` позволяют отличить
полный набор от sample/empty. Даже `full` не гарантирует, что Telegram ещё
отдаст файл: ссылка на документ может устареть, пользовательская MTProto-сессия
или сеть быть недоступны. Реальный ответ этого сервера здесь не проверен.

Добавлен локальный резерв для 29 моделей Heart Locket из 32 имён текущего пула:
при отсутствии document_id сервер по точному имени выдаёт отрицательный
внутренний ID модели в инвентаре; база и выпавшая модель не изменяются. Если
известен документ Telegram и он есть в манифесте, сначала пробуется Telegram,
затем соответствующий локальный TGS. Паттерн этим не восстанавливается.
Источники, ограничения прав и три отсутствующие модели описаны в
`authbot/assets/gift_models/README.md`.

На следующем скриншоте модель #2 — **Shield of Sun**. Её нет среди 29 локальных
TGS и нет в сохранённом статическом пуле, но два сторонних справочника отдельно
приводят документ `5226650538359158786` для Heart Locket: [xgift, commit
48074a9d](https://github.com/aiofake/xgift/blob/48074a9d22489e0749751ceaf3b4d5f68ce5f05e/xgift/gift_data.json)
и [NFTsMine, commit 5087e94f](https://github.com/NFTsMine/NFTsMine/blob/5087e94f3a77713f2791370e2059e1ee51b21556/Database/Emoji/Heart%20Locket.json).
Это сторонние данные, не официальное подтверждение Telegram. Сервер при отсутствии
ID подставляет его **только в ответ**, затем пытается запросить нужный документ у
Telegram через `messages.getCustomEmojiDocuments`. Telegram может его не вернуть
или отказать сессии; настоящий файл и отображение Shield of Sun на сервере/устройстве
не проверены. Пока байты не получены, модель останется пустой, не подменяется другой.

Для применения нужно развернуть обновлённый AuthBot **вместе с assets и
`gift_model_fallbacks.py`**, затем выпустить Android-версию, если требуется
обход старого кеша Pepe и исправление логики Android. APK и реальное устройство
в этой задаче не проверялись; проверьте в том числе анимацию, повторный вход и
отображение чужого профиля. До этого нельзя утверждать, что проблема устранена
в установленном приложении.
