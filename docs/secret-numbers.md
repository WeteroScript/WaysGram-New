# Секретные номера: почему вход падал на «+0 000 0000»

С устройства: на экране входа выбран «Секрет», введён номер `+0 000 0000` — диалог
«Invalid phone number»; в боте то же число встречает ответом «Введите номер в международном
формате».

## Причина

Секретными считались только пять ровно совпадающих значений: `+0`, `+111`, `+333`, `+666`,
`+999` (`authbot/virtual_numbers.py::SECRET_NUMBERS`, клиентский
`WaysGramMapper.isSecretNumberDigits`). Любые цифры после префикса уже не проходили:

* `authbot/bot.py::normalize_admin_number` → `None`, бот отвечает ошибкой формата;
* `POST /api/auth/request-code` → 400, клиент показывает общий текст `InvalidPhoneNumber`.

То есть аккаунт с номером вида `+0 000 0000` нельзя было ни создать в боте, ни использовать для
входа в приложение — при этом подсказка бота и экран входа рекламировали «секретный номер: +0».

## Что изменено

* `authbot/virtual_numbers.py`: секретное пространство — это префикс секретного номера плюс
  любые цифры после него (`SECRET_SPACE = \+(?:0|111|333|666|999)[0-9]{0,12}`), плюс появились
  `is_secret_number()` и `normalize_number()` (убирает пробелы/скобки/дефисы: `+0 000 0000` →
  `+00000000`).
* `POST /api/auth/request-code` и `/api/auth/verify-code` нормализуют номер и принимают его как
  ввёл человек; текст ошибки 400 теперь объясняет допустимые форматы, включая секретные.
* `authbot/bot.py`: группировка номеров под кнопкой «Секрет» и валидация админского ввода
  используют `is_secret_number`; подсказки (создание аккаунта и ответ на неверный ввод) прямо
  говорят, что после секретного префикса можно дописывать цифры. Американское сокращение
  10 цифр (`+1…`) больше не применяется к номерам, начинающимся с `0`.
* `WaysGramMapper.isSecretNumberDigits`: префикс + цифры (до 15), поэтому экран входа считает
  `+0 000 0000` секретным логином и не пытается разобрать его как код страны.
* `WaysGramTransport.mapError`: для авторизационных 400 от сервера показывается объяснение
  сервера (`«+код страны и 7–14 цифр либо секретный номер…»`, «Номер не закреплён за аккаунтом»)
  вместо безликого `Invalid phone number`.

## Как теперь выглядит рабочий путь

1. Бот: «Создание аккаунта» → `+0 000 0000` → аккаунт с номером `+00000000`.
2. Приложение: страна «Секрет», номер `+0 000 0000` → `auth.sendCode(+00000000)` → код приходит
   в чат бота → вход.

## Проверки

```bash
python3 -m pytest scripts/test_android_login_numbers.py -q     # сервер + клиент, статически
cd authbot && python3 -m pytest tests/test_bot.py tests/test_messenger_api.py -q
```

`tests/test_bot.py::test_admin_number_input_accepts_secret_and_prefixed_numbers` и
`tests/test_messenger_api.py::test_secret_numbers_support_admin_creation_and_otp_login` расширены
сценарием `+0 000 0000`: нормализация, создание аккаунта, `request-code` и `verify-code`.
