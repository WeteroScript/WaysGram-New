# Имя в чатах вместо номера телефона

Жалоба с устройства: в списке чатов и в заголовке переписки у части собеседников вместо имени
показывался номер телефона (`+7 999 123-45-67`), у остальных — нормальное имя.

## Откуда брался номер

Имя в клиенте собирается в `WaysGramMapper.toUser(...)`: раньше единственным источником был
`display_name` из ответа сервера, а телефонные значения принимались как есть. Второй путь —
`UserObject.getUserName(...)` из стока Telegram: если у пользователя нет имени, но есть
`user.phone`, он подставляет отформатированный номер. Достаточно было пустого имени в записи,
сохранённой в кэше клиента, чтобы в чате появились цифры.

## Что изменено

* `WaysGramMapper.nameFromJson(...)` перебирает `display_name`, `full_name`, `name`, затем
  `first_name` + `last_name`; значения, похожие на телефон (`looksLikePhone`), именем не
  считаются. Служебная строка `"null"` (JSON `null`, приведённый `optString`) тоже отбрасывается.
* Если имени нет — показывается ник (`username`), и только потом подпись `User <id>`.
* `UserObject.getUserName(...)`: для WaysGram-аккаунтов номер телефона больше не становится
  именем — он остаётся в профиле, но не в заголовке чата. Для настоящего Telegram номер
  по-прежнему последний вариант, как и было.
* `authbot/bot.py`: `ensure_account(...)` больше не записывает имя, похожее на телефон, и **не
  перетирает** имя, выбранное человеком в приложении, при повторном входе в бота (раньше каждое
  `/start` перезаписывало `display_name` именем из Telegram). Записанный ранее номер при
  следующем входе заменяется на настоящее имя.

## Проверки

```bash
python3 -m pytest scripts/test_android_gift_number_and_names.py -q
```

Тест читает части архива: убеждается, что маппер отбрасывает телефонные имена, что
`getUserName` не подставляет номер для WaysGram и что перелив «#???» использует зеркальный
тайл с симметричной палитрой (иначе рывок вернётся).
