# Собственный подарок WaysGram: Mellstroy

Первый подарок, который принадлежит WaysGram, а не Telegram: у него свои анимированные
модели улучшения, своя цена и свой остаток. Магазин, улучшение, черты и карточки
работают теми же путями, что и у подарков Telegram, — клиент разницы не чувствует.

## Что где лежит

| Что | Где |
| --- | --- |
| id подарка | `7390000000000000001` (Telegram такого id не знает) |
| настройки (название, цена, остаток, позиция) | `authbot/waysgram_gifts.py`, словарь `GIFTS` |
| встроенные анимации | `authbot/assets/gift_models/7390000000000000001/` |
| шансы моделей | `authbot/gift_upgrade_pools.json` + `gift_upgrades.SPECIAL_MODELS` |
| конвертер исходных клипов | `scripts/prepare_gift_model_pack.py` |
| обзор всех моделей | `gift_models_preview.png` |

## Анимации

Пак содержит 15 файлов WebM с альфа-каналом и 15 PNG-постеров:

* `main.webm` — `OSNOVNOI`, картинка подарка в магазине (не улучшенный подарок);
* 14 моделей улучшения с отрицательными документ-id `-7700000000000002…-7700000000000013`
  (две самые редкие — `-7700000000000000` «Привет» и `-7700000000000001` «Танцует»).

Исходные клипы были без альфы: анимация нарисована на чёрном фоне. Конвертер убирает
только те чёрные пиксели, которые связаны с краем кадра, поэтому чёрная одежда и обувь
остаются непрозрачными; затем мат эрозируется на 1 px и немного размывается, чтобы у
края не оставалось тёмной каймы. Кодирование — `libvpx-vp9`, `yuva420p`,
`-auto-alt-ref 0 -row-mt 0 -metadata alpha_mode=1`, иначе альфа теряется.

Клиент забирает модели через `/api/telegram/gifts/<id>/attributes/<document_id>`:
отрицательный id отдаётся из встроенного пака, без обращения к Telegram.

## Цена, остаток и каталог

Запись каталога — обычная строка `telegram_mtproto_gift_catalog` с отметкой
`is_waysgram=1`, цена и остаток — строка `telegram_gift_prices`:

* цена по умолчанию **5000★**, остаток **1000**, улучшение **25★**;
* `INSERT OR IGNORE` при старте: значения администратора не перезаписываются;
* синхронизация каталога Telegram никогда не выключает нашу запись (`is_waysgram=1`
  исключён из `SET is_available=0`), префетч артавука её тоже пропускает;
* в магазине подарок стоит после подарков Telegram (позиция `1_000_000`).

В AuthBot есть отдельный экран **«Подарки WaysGram (свои модели)»** (`wgadm:wggifts`):
цена, остаток, «Убрать из каталога / Вернуть в каталог» и «Скрыть (цена 0, остаток 0)».
Экран Telegram-подарков, массовый импорт и «скрыть все» этот подарок не трогают.

## Шансы улучшения

Две модели выпадают точными независимыми бросками, остальные 12 — взвешенный пул на
1000 ‰ (суммарно ровно 1000):

| модель | шанс |
| --- | --- |
| Привет | 0.05 % (`one_in: 2000`) |
| Танцует | 0.1 % (`one_in: 1000`) |
| Удовлетворённость | 150 ‰ |
| Мама птица | 130 ‰ |
| Зарядка | 120 ‰ |
| Тужится | 110 ‰ |
| Омайгад | 100 ‰ |
| Пам-пам-пам-пам | 90 ‰ |
| Разбил | 80 ‰ |
| Злой | 70 ‰ |
| Неудачность | 60 ‰ |
| Средневековый | 40 ‰ |
| Я уже красный | 30 ‰ |
| Страшно | 20 ‰ |

Узоры и фоны не перерисовываются: берётся набор реального подарка Telegram (сейчас
«Vice Cream»: 300 узоров и 80 фонов), потому что Телеграм публикует их как маленькие
анимации и цветовые схемы. Модели донора никогда не используются. Отдельные броски
считаются с общим знаменателем, поэтому 0.05 % и 0.1 % остаются именно такими, а не
размываются порядком проверок.

перезапуск не перезаписывает значения администратора; витрина, стикер и атрибуты;
переключатель каталога в AuthBot; полный цикл улучшения с выдачей WebM-анимации.
